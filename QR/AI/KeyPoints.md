| Key Point | Note |
|-----------|------|
| attention | A mechanism that lets each position in a sequence pull information from other positions, weighted by relevance rather than by distance. Each token is projected into three vectors: a query (what I'm looking for), a key (what I offer), and a value (what I'd contribute). The score for token i attending to token j is query_i · key_j, scaled by √d_k, softmaxed across all j into weights that sum to 1, then used to take a weighted average of the value vectors. Output = softmax(QKᵀ/√d_k)·V. "Multi-head" means doing this h times in parallel with separate projections and concatenating, so different heads can specialize (syntax, coreference, position). Crucially it's order-agnostic by construction — hence positional encodings — and fully parallel across positions, which is why it replaced RNNs.|
| embedding | A learned mapping of a discrete item (token, word, sentence, image, user, product) to a dense list of floating-point numbers, such that items with similar meaning land close together in that space. It's both the vector itself ("the embedding of this sentence") and the lookup layer that produces it. The key property is that geometry encodes meaning — nothing is being "embedded into" anything in the ordinary sense. |
| feature / dimension | Any individual measurable input property the model uses (age, pixel intensity, token frequency). A dimension is one coordinate/slot of a vector — position i in the array. In classical ML features were hand-engineered and human-readable; in deep learning the dimensions of a learned embedding are latent features, and an individual axis usually has no interpretable meaning on its own. Counts are routinely 384, 768, 1536, 3072 — nothing to do with spatial dimensions. (The meaning is: in the classical (pre-deep-learning) era, a human decided what each input column represented — age, income, word count, pixel brightness — so every dimension had a name you could point at. In deep learning the model learns its own internal representation, so dimension 412 of a 768-dimensional embedding means whatever the training process made it mean, and usually isn't interpretable in isolation.) |
| grok | 1. Informal: to understand something deeply and intuitively rather than by surface pattern-matching. From Heinlein's Stranger in a Strange Land (1961), long predating AI; borrowed by programmers ("do you grok pointers?").  
2. Technical — "grokking": a real, documented training phenomenon (Power et al., 2022). A model trains on a small algorithmic task, reaches ~100% training accuracy quickly by memorizing, and test accuracy stays at chance — then, after far more training past that point, test accuracy abruptly jumps to ~100%. Generalization arrives long after memorization, discontinuously. It's studied as evidence that networks first memorize, then reorganize into a general circuit under weight decay / regularization pressure.  
3. Product name: Grok, xAI's chatbot, named after the Heinlein word. Unrelated to the phenomenon.|
| hallucination | When a model produces fluent, confident output that isn't grounded in its training data, in the source provided to it, or in reality — fabricated citations, invented APIs, plausible-but-wrong dates. Two subtypes: intrinsic (contradicts the source text it was given) and extrinsic (unsupported by and unverifiable against the source, though possibly true). It isn't a bug in the ordinary sense: the objective is next-token likelihood, which rewards plausibility, not truth, and there's no lookup step where the model checks a fact against a store. Contributing factors: gaps or noise in training data, sampling randomness at decode time, and training/evaluation regimes that reward confident answers over abstention. Mitigations are all about grounding — retrieval (RAG), tool/API calls, forced citation, and calibrated "I don't know" — not about the model trying harder. |
| self-attention | Attention where Q, K and V all come from the same sequence: the sequence relating to itself. Contrast cross-attention, where queries come from one sequence and keys/values from another (decoder attending to encoder output, or text attending to image patches). "Causal" or "masked" self-attention additionally blocks position i from seeing positions > i, which is what makes a decoder-only LLM able to train on all positions at once while still only ever predicting forward. Self-attention is the core layer of the transformer; the "attention is all you need" claim was that you can drop recurrence and convolution and keep only this. |
| semantics / data element | A data element is the atomic unit of data that carries a defined meaning (a field, an attribute, one addressable value). Semantics is that meaning itself, as opposed to syntax (its format/structure) — so "semantic search" matches on meaning rather than matching keyword strings, and a "semantic layer" maps raw columns to business meaning. The point is the deliberate split: the same data element can have identical syntax and completely different semantics. |
| token | In AI data transfer, a token is roughly equal to 3/4 word, so roughly 130-150 words will cost about 200 tokens. |
| vector | Simply an ordered array of numbers ("Ordered" means position matters: each slot has a fixed meaning, and the numbers stay in the order the model produced them. Two things follow from "ordered" in this sense: 1. Slot identity is fixed. Position 0 of every embedding from a given model represents the same latent feature. Comparing vectors means comparing slot 0 to slot 0, slot 1 to slot 1, and so on. 2. Reordering destroys it. If you sorted that array ascending, you'd get a valid array of numbers but a meaningless vector — you've scrambled which feature each number belongs to. [0.55, 0.12] and [0.12, 0.55] are two different vectors pointing in different directions.) — a single point in high-dimensional space. Direction and magnitude only matter indirectly, via similarity measures (cosine similarity, dot product, Euclidean distance). "Vector database", "vectorize", "vector store" all just mean working with these number arrays. |

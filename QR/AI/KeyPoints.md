| Key Point | Note |
|-----------|------|
| embedding | A learned mapping of a discrete item (token, word, sentence, image, user, product) to a dense list of floating-point numbers, such that items with similar meaning land close together in that space. It's both the vector itself ("the embedding of this sentence") and the lookup layer that produces it. The key property is that geometry encodes meaning — nothing is being "embedded into" anything in the ordinary sense. |
| feature / dimension | Any individual measurable input property the model uses (age, pixel intensity, token frequency). A dimension is one coordinate/slot of a vector — position i in the array. In classical ML features were hand-engineered and human-readable; in deep learning the dimensions of a learned embedding are latent features, and an individual axis usually has no interpretable meaning on its own. Counts are routinely 384, 768, 1536, 3072 — nothing to do with spatial dimensions. (The meaning is: in the classical (pre-deep-learning) era, a human decided what each input column represented — age, income, word count, pixel brightness — so every dimension had a name you could point at. In deep learning the model learns its own internal representation, so dimension 412 of a 768-dimensional embedding means whatever the training process made it mean, and usually isn't interpretable in isolation.) |
| semantics / data element | A data element is the atomic unit of data that carries a defined meaning (a field, an attribute, one addressable value). Semantics is that meaning itself, as opposed to syntax (its format/structure) — so "semantic search" matches on meaning rather than matching keyword strings, and a "semantic layer" maps raw columns to business meaning. The point is the deliberate split: the same data element can have identical syntax and completely different semantics. |
| token | In AI data transfer, a token is roughly equal to 3/4 word, so roughly 130-150 words will cost about 200 tokens. |
| vector | Simply an ordered array of numbers ("Ordered" means position matters: each slot has a fixed meaning, and the numbers stay in the order the model produced them. Two things follow from "ordered" in this sense: 1. Slot identity is fixed. Position 0 of every embedding from a given model represents the same latent feature. Comparing vectors means comparing slot 0 to slot 0, slot 1 to slot 1, and so on. 2. Reordering destroys it. If you sorted that array ascending, you'd get a valid array of numbers but a meaningless vector — you've scrambled which feature each number belongs to. [0.55, 0.12] and [0.12, 0.55] are two different vectors pointing in different directions.) — a single point in high-dimensional space. Direction and magnitude only matter indirectly, via similarity measures (cosine similarity, dot product, Euclidean distance). "Vector database", "vectorize", "vector store" all just mean working with these number arrays. |
